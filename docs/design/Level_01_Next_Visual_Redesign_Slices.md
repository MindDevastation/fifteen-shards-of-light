# Level_01 — Next Visual Corrective Pass

Статус: post-PR#92 corrective planning  
Назначение: **единый source of truth** для следующего визуального/UX corrective pass по Level_01.  
Цель: перейти от серии мелких параметрических фиксов к более заметному приближению к **конечному художественному варианту**.

---

## 1. Общая цель прохода

Следующий проход должен исправить не только технические дефекты, но и **визуальную архитектуру** проблемных частей Level_01.

Ключевая идея:
- меньше микротюнинга коэффициентов;
- больше структурных изменений в сценах, UI и VFX;
- каждое изменение должно быть проверено:
  1. на соответствие задаче,
  2. на отсутствие регрессий,
  3. повторной проверкой уже после первого self-review.

## 3. Source of truth по новым правкам

### 3.1 Soul Orb

Новый текст prompt:

```text
Поднять сферу
```

Важно:
- не переиспользовать напрямую текущую generic prompt-логику без адаптации;
- для Soul Orb создать **отдельную reusable scene** / presentation-layer решение, чтобы это был отдельный контролируемый объект, а не случайный хак поверх текущего prompt;
- визуально стиль должен оставаться совместимым с остальными world prompts.

### 3.2 Finale text reveal

Нужно:
- заметно **ускорить** появление текста относительно текущей версии;
- текст по-прежнему не должен вылезать за рамку;
- нужно вычислять usable text area **от размеров рамки**;
- целевая text area = **75% от внутреннего размера рамки**;
- текстовый блок должен быть автоматически размещен **внутри рамки**;
- анимацию исчезновения / закрытия окна замедлить примерно в **2.5 раза** относительно текущей версии;
- допускается снова попробовать reveal **слева направо**, но только если это:
  - не выглядит как печатная машинка,
  - не дает некрасивых обрезанных слов,
  - остается мягким и читаемым.

Также учесть предыдущие замечания:
- текст должен быть легче читаем;
- presentation должна ощущаться как эмоциональный payoff, а не затянутый технический fade.

### 3.3 Портал

Текущее направление с тонкими линиями и плоскими слоями признано недостаточным.

Новая целевая идея:
- у портала должно быть **6 плотных рукавов**;
- рукава должны читаться не как линии, а как **скопления светящихся огней**, по аналогии с ощущением от Soul Shard / light motes;
- портал должен оставаться:
  - вертикальным,
  - объемным,
  - плотным,
  - быстрым,
  - хорошо читаемым.

То есть направление:
- меньше «нарисованных спиральных линий»;
- больше «6 плотных световых рукавов из glowing particles / motes / clustered lights».

### 3.4 Облака

Предыдущий вывод принят:
- облака все еще недостаточно объемные;
- нужен не очередной минимальный parameter tweak, а более заметное улучшение формы/глубины.

### 3.5 Рамка финального окна и листья

Предыдущий вывод принят:
- рамка все еще слишком процедурная;
- листья должны расти из веток визуально убедительнее.

Отдельная целевая задача:
- если возможно, вычислять **координату края ножки листика** и привязывать ее к координате соответствующей ветки / сегмента рамки;
- визуально лист должен выглядеть как **растущий из ветки**, а не как наклеенный поверх нее.

# Slice 2 — Finale text layout from frame geometry

## Цель
Перестроить layout финального текста так, чтобы он вычислялся от размеров рамки, а не от приблизительных ручных смещений.

## Что сделать
- вычислить bounds рамки / usable inner area;
- выделить text safe area размером **75% от внутреннего размера рамки**;
- поместить текстовый блок внутрь этой зоны;
- гарантировать, что текст не залезает за декор;
- сохранить reuse final overlay.

## Дополнительные требования
- text positioning должно быть устойчивым минимум для:
  - 1920×1080,
  - 1280×720.

## Acceptance criteria
- текст стабильно находится внутри рамки;
- нет пересечений с декором;
- layout не выглядит случайным.

# Slice 3 — Finale text reveal / pacing / close timing

## Цель
Сделать final text reveal заметно лучше по ощущению.

## Что сделать
- ускорить reveal текста относительно текущей версии;
- сохранить мягкость анимации;
- исследовать reveal слева направо, но разрешить его только если:
  - слова читаются красиво,
  - нет уродливого clipping,
  - не появляется ощущение typewriter;
- если left-to-right reveal не проходит по качеству — выбрать более удачный вариант (например soft veil / masked reveal / alpha+movement);
- замедлить анимацию исчезновения / закрытия примерно в **2.5 раза**.

## Acceptance criteria
- reveal заметно живее;
- текст читается быстрее и приятнее;
- close animation не выглядит резко оборванной;
- окно все еще ощущается эмоционально, а не технически.

# Slice 4 — Portal architecture redesign (6 dense light sleeves)

## Цель
Сделать портал ближе к целевому художественному варианту, а не просто еще одной версией текущего line-based portal.

## Ключевая художественная цель
Портал должен состоять из **6 плотных рукавов**, визуально похожих на **скопления светящихся огней / motes**, а не на набор тонких линий.

## Что сделать
- сохранить вертикальность;
- сохранить 6-arm concept;
- переработать presentation рукавов в сторону clustered lights / glowing particle sleeves;
- сделать рукава:
  - плотными,
  - объемными,
  - читаемыми,
  - более цельными как объект;
- сохранить или улучшить rim/outline;
- сохранить ощущение портала как прохода, а не просто визуального эффекта.

## Желательное направление реализации
Допустимы решения через комбинацию:
- particle sleeves,
- clustered light motes,
- guided particle paths,
- orbiting / flowing light streams,
- supporting soft veil,
- supporting rim mesh / outline.

Не застревать в одном только parameter tuning текущих тонких shader lines.

## Acceptance criteria
- 6 рукавов явно читаются;
- они воспринимаются как плотные световые потоки;
- портал выглядит более объемным;
- сохраняется silhouette readability;
- эффект не превращается в белый blob.

После каждого слайса:

- `git diff --stat`

## 6. Mandatory final review protocol

После реализации Codex обязан сделать три этапа проверки:

### Review Pass 1 — Against this MD
- пройтись по каждому slice;
- отметить, что реализовано и что нет;
- ничего не пропустить.

### Review Pass 2 — Against actual code/resources
- повторно открыть все затронутые файлы;
- проверить, что решение действительно соответствует intention, а не только формально похоже;
- проверить регрессии.

### Review Pass 3 — Review the review
- отдельно проверить, не пропущены ли пункты в Review Pass 1 и Review Pass 2;
- сверить финальный handoff с фактическими изменениями.

# Codex Task — Implement Level_01 Next Visual Corrective Pass

Работай по файлу:

```text
/mnt/data/Level_01_Next_Visual_Redesign_Slices.md
```

Этот файл является **source of truth** для задачи.

---

## Задача

Реализовать corrective pass по Level_01 строго по md файлу выше.

Ключевые требования:
- выполнять работу **по слайсам**;
- не переходить к следующему слайсу, пока предыдущий не завершен;
- после завершения слайса **не останавливаться** и продолжать следующий;
- в конце выполнить **повторную проверку реализации**;
- после этого выполнить **проверку самой проверки**, чтобы убедиться, что ничего не пропущено.

---

## Жесткие правила

1. Перед началом работы прочитай целиком:

```text
/mnt/data/Level_01_Next_Visual_Redesign_Slices.md
```

2. Используй этот md файл как главный источник истины.

3. Работай только по указанным там slice-блокам.

4. После каждого slice обязательно:
- проверить затронутые файлы;
- выполнить быстрые валидации;
- убедиться, что нет регрессий.

5. Не завершай работу после первого успешного прохода.

---

## Порядок работы

### Этап 1 — Preflight
- выполни preflight checks;
- зафиксируй branch / SHA / baseline;
- если baseline не подходит — остановись с `BLOCKER`.

### Этап 2 — Реализация по slice-ам
Реализуй все slices из md файла по порядку:
- Slice 0
- Slice 1
- Slice 2
- Slice 3
- Slice 4
- Slice 5
- Slice 6
- Slice 7
- Slice 8

Если какой-то slice требует только audit без изменений — это нужно явно отметить в handoff.

### Этап 3 — Review Pass 1
После завершения всех slices:
- еще раз открой md файл;
- проверь выполнение **каждого** slice;
- составь список выполнено / не выполнено / частично.

### Этап 4 — Review Pass 2
- заново открой и перепроверь все измененные файлы;
- убедись, что код и сцены реально соответствуют intention;
- убедись, что нет hidden regressions;
- отдельно проверь UI, VFX, scene wiring, timings, reusable behavior.

### Этап 5 — Review Pass 3 (проверка проверки)
- проверь, не пропущены ли пункты в Review Pass 1;
- проверь, не пропущены ли пункты в Review Pass 2;
- перепроверь финальный handoff на соответствие реальным изменениям.

### Этап 6 — Final polish
- если во время review найдены пропуски — исправь их;
- после исправлений снова кратко перепроверь затронутые части.

### Этап 7 — Final report
Обнови development report и подготовь финальный handoff.

## Validation

Минимально обязательно:

После каждого slice:
```bash
git status --short --branch --untracked-files=all
git diff --check
git diff --stat
```

После всех изменений:
```bash
godot --headless --path . --quit --check-only
timeout 180s godot --headless --editor --path . --quit
```

Если первый editor import timed out во время import:
- повторить один раз;
- первый timeout не считать parse failure;
- pass заявлять только если второй запуск успешен.

Выполнить targeted validation для всех затронутых сцен/скриптов.

1. branch / starting SHA / final local SHA;
2. список commits в порядке создания;
3. список созданных файлов;

6. по каждому slice:
   - что было сделано;
   - что не потребовало изменений;

7. результат Review Pass 1;
8. результат Review Pass 2;
9. результат Review Pass 3;
10. automated validation status;
11. graphical QA actually performed;
12. performance actually measured;
13. updated report path;
14. merge performed: no;
15. auto-merge enabled: no;
16. new PR created: no (если действительно не создавался).

## Особо важные акценты

### Soul Orb
- текст должен быть **ровно** `Поднять сферу`;
- должно быть отдельное reusable scene/presentation решение.

### Finale overlay
- text area = 75% от размера рамки;
- текст должен быть внутри рамки;
- reveal быстрее текущего;
- исчезновение медленнее текущего примерно в 2.5 раза;
- если left-to-right reveal дает плохое визуальное качество — выбрать лучший вариант и честно зафиксировать решение.

### Portal
- 6 плотных рукавов;
- рукава как скопления светящихся огней / light clusters / motes;
- не просто еще один pass по thin lines;
- главное — сделать визуально заметный шаг к конечному варианту.

### Clouds
- нужен заметный объемный прогресс, а не только косметический parameter tweak.

### Frame / leaves
- проверить и по возможности реализовать attachment leaf stem edge к ветке,
  чтобы листья выглядели растущими из веток.
